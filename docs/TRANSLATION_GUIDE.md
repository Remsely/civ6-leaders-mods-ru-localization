# Руководство по переводу и устройству мода

## Как устроены моды Civ VI (коротко)

- Мод — папка с файлом `.modinfo` (XML), у каждого мода есть уникальный GUID (`<Mod id="…">`).
- В `.modinfo` перечислены **действия** (`UpdateText`, `UpdateDatabase`, …) и **файлы**. Действия бывают для главного меню (`FrontEndActions`) и для партии (`InGameActions`), поэтому текст подключается в обоих местах.
- Тексты лежат в XML: `<Replace Tag="LOC_…" Language="ru_RU"><Text>…</Text></Replace>`. Одному тегу соответствует по одной строке на язык, поэтому наши русские строки **не конфликтуют** с английскими строками исходного мода: они просто добавляются рядом.
- Действие можно привязать к условию. Мы используем `ModInUse` с GUID исходного мода: перевод подключается, только если исходный мод включён в партии.

## Архитектура репозитория

```
mod.json                    параметры нашего мода (GUID, название, версия, папка)
mods.csv                    список модов, которые нужно перевести (id, название, путь)
src/<ИмяМода>/              один исходный мод = одна папка
    meta.json               название, workshop_id, GUID исходного мода, status (draft|ready)
    ru_RU.xml               перевод (допускается несколько *.xml)
tools/civ6loc.py            extract / validate / build / install / uninstall / status
dist/                       результат сборки (не коммитится)
docs/                       документация
```

Принципы:

- **Один мод — одна папка.** Добавить мод = добавить папку, ничего больше не править.
- **`.modinfo` не пишется вручную.** Его генерирует `build` по всем готовым папкам из `src/`: критерии, действия и список файлов всегда согласованы.
- **Проверки автоматические.** Ошибки поймает `validate`, а не игрок в партии.
- **Статус `draft`/`ready`.** Неготовые переводы в сборку не попадают, поэтому игрок не увидит наполовину русскую страницу.

## Как добавить перевод нового мода

1. Выберите мод из `mods.csv` (колонка `id` — это workshop id и имя папки в Steam).
2. Создайте черновик:
   ```powershell
   python tools/civ6loc.py extract <workshop_id> <Автор_Цивилизация_Лидер>
   ```
   Имя папки — латиница, без пробелов, вида `JFD_Russia_IvanIV`. Команда прочитает `.modinfo` исходного мода, возьмёт его GUID и английские строки и создаст `src/<имя>/meta.json` и `ru_RU.xml` (в нём пока английский текст, `status: draft`).
3. Переведите тексты в `ru_RU.xml` (правила ниже).
4. Проверьте: `python tools/civ6loc.py validate <имя>`.
5. Поставьте в `meta.json` `"status": "ready"`.
6. Протестируйте в игре: [TESTING.md](TESTING.md).
7. Прогресс по всему списку: `python tools/civ6loc.py status`.

## Правила перевода

**Не менять:**
- теги (`LOC_…`) и атрибут `Language="ru_RU"`;
- плейсхолдеры: `[ICON_FAITH]`, `[NEWLINE]`, `[COLOR_…]`, `{LOC_…}`, `[LOC_…]`, `{1_Name}`, `%1`. Их количество должно совпадать с оригиналом.

**Названия сущностей** (теги вида `LOC_LEADER_*_NAME`, `LOC_UNIT_*_NAME`, `LOC_BUILDING_*_NAME`, `LOC_DISTRICT_*_NAME`, `LOC_IMPROVEMENT_*_NAME`, `LOC_CIVILIZATION_*_NAME`, `LOC_CIVILIZATION_*_ADJECTIVE`) в русской игре записываются **шестью падежами через `|`** и с `Gender`/`Plurality`, как в официальной локализации:

```xml
<Replace Tag="LOC_LEADER_JFD_IVAN_IV_NAME" Language="ru_RU">
    <Text>Иван IV|Ивана IV|Ивану IV|Ивана IV|Иваном IV|Иване IV</Text>
    <Gender>masculine</Gender>
    <Plurality>1</Plurality>
</Replace>
```
Порядок падежей: именительный, родительский, дательный, винительный, творительный, предложный. `Plurality` — 1 для единственного числа и 2 для множественного («Стрельцы»). `Gender` — `masculine`, `feminine` или `neuter`. Названия повесток, особенностей (`TRAIT`), способностей (`ABILITY`) и страниц Цивилопедии — обычный текст без падежей.

**Терминология:** придерживайтесь официального русского перевода игры. Основные термины: вера, лояльность («ед. лояльности»), религия, великий полководец, посол, содержание (юнитов), мушкетёры, Тёмный/Золотой век, Порох (технология). Официальный текст лежит в `…\Sid Meier's Civilization VI\Base\Assets\Text\Vanilla_ru_RU.xml`, оттуда удобно сверять формулировки и подсмотреть перевод схожих фраз (например, «капсула» Цивилопедии у многих лидеров взята из текста Петра Великого).

**Орфография:** буква «ё» не используется, как в официальном тексте игры. Для речи персонажей сохраняйте характер оригинала.

**Исторические тексты** (`CHAPTER_HISTORY_PARA_*`) переводятся полностью, `[NEWLINE][NEWLINE]` оставляются на тех же местах.

## Ограничения и известные риски

- `extract` читает английские тексты из XML (`<Row>`/`<Replace>`) и из SQL-файлов (`INSERT … INTO LocalizedText (Language, Tag, Text) VALUES …`), перечисленных в `UpdateText` исходного мода. Так сделаны Bavaria и Leugi's Mexico. Строки вида `INSERT … SELECT … FROM LocalizedText` (копирование чужих тегов, например диалогов Людвига у Баварии) пропускаются: русский текст для них берётся из игры. Наш перевод всегда пишется в XML.
- Если автор исходного мода обновит его (новые/удалённые теги), `validate` покажет расхождения: «нет перевода» или «тега нет в исходном моде». При смене GUID — ошибка.
- В мастерской есть пак **«[RUS] Localization Pack»** (id `3661835263`), в нём пока лежат пустые папки под многие моды из нашего списка. Если автор пака позже добавит перевод тех же модов, строки совпадут по тегу и языку, и какая из них применится, определяет порядок загрузки (`LoadOrder`; у нас он задаётся как `load_order` в `mod.json`) — это нужно будет проверить в игре. Имеет смысл проверять пак перед началом работы над новым модом.
- Для части модов (Papal States, Soviet Union, Italy, Rome и др.) в игре уже есть **частичный** перевод от самих авторов (ru-файлы внутри мода, около 20–85% строк). Наш `ru_RU.xml` для таких модов должен содержать **все** строки (`extract` берёт английский оригинал, существующие частичные переводы не учитываются). Строки с теми же тегами в двух местах — тот же вопрос порядка загрузки, что и выше.
